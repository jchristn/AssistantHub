TesseraCloud Environment Configuration: Staging (staging)

Document ID: eng-tesseracloud-config-staging. Owner: Platform Engineering. Last updated: 14 July 2025. This page describes the staging environment only. Development and production use different hosts, ports and settings; see their own configuration pages.

Environment summary

  • Environment name (TC_ENV): staging
  • Region: euw1 only, no disaster-recovery replica.
  • Forge environment: tesseracloud-staging. Every merge to main is deployed automatically after the integration test stage passes.
  • Data: synthetic telemetry plus a fleet of 40 test TS-4 gateways and 25 TS-4e edge nodes in the Leeds engineering lab and the Austin demo room.
  • Access: TesseraCloud engineers and QA; customer support staff have read-only access for release previews.

Deployment

Staging deployments happen automatically on merge to main. A release candidate must run in staging for at least 48 hours without a SEV3 or higher defect before it can be promoted to production.
