TesseraCloud API Rate Limits

Document ID: prod-tesseracloud-api-rate-limits-v1 | Version: 1 | Effective: 2024-06-03 | Owner: TesseraCloud Platform Team

Overview

The TesseraCloud REST API (base URL https://api.tesseracloud.meridian-instruments.com) applies rate limits to protect service quality for all customers. Limits are applied per tenant, across all API keys belonging to that tenant. The same limits apply to every subscription plan.

Limits

LimitValue
Requests per tenant, all endpoints600 requests per minute
Burst allowance100 requests per 10 seconds
GET /v2/devices/{id}/readings120 requests per minute per tenant
Maximum page size (limit parameter)1000 items
Default page size100 items

Requests to the readings endpoint count towards both the endpoint-specific limit and the overall tenant limit.

When a limit is exceeded

The API returns HTTP 429 Too Many Requests with a Retry-After header giving the number of seconds to wait before retrying. Clients should wait at least the Retry-After value and should add random jitter to avoid synchronised retries from multiple workers.

Recommendations

  • Request readings for a time range with the from and to parameters rather than polling for the latest reading repeatedly.
  • Use the maximum page size of 1000 when backfilling history.
  • Subscribe to webhooks (/v2/webhooks) for alarm notifications instead of polling /v2/devices/{id}/alarms.
  • Cache device metadata from /v2/devices; it changes rarely.

Requesting higher limits

Customers with a genuine need for higher throughput can request a temporary limit increase through a Meridian Support Centre ticket. Increases are granted for up to 30 days, for example for an initial historical migration.
