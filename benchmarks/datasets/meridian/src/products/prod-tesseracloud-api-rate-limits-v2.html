TesseraCloud API Rate Limits

Document ID: prod-tesseracloud-api-rate-limits-v2 | Version: 2 | Effective: 2025-07-01 | Supersedes: prod-tesseracloud-api-rate-limits-v1 | Owner: TesseraCloud Platform Team

Overview

The TesseraCloud REST API (base URL https://api.tesseracloud.meridian-instruments.com) applies rate limits to protect service quality for all customers. From 1 July 2025 (TesseraCloud release 2025.2), limits depend on the tenant's subscription plan and the readings endpoint is limited per device rather than per tenant. Limits apply across all API keys belonging to a tenant.

Webhook deliveries from TesseraCloud to your endpoints do not count towards any rate limit.

Rate limit headers

Every API response includes the following headers:

  • X-RateLimit-Limit: the per-minute limit that applies to the request.
  • X-RateLimit-Remaining: requests remaining in the current window.
  • X-RateLimit-Reset: Unix timestamp (seconds) at which the window resets.

When a limit is exceeded

The API returns HTTP 429 Too Many Requests with error code TC-ERR-429 and a Retry-After header in seconds. Clients must honour Retry-After and use exponential back-off with jitter. An API key that continues to receive 429 responses for 15 consecutive minutes is suspended for 10 minutes, and the Tenant Owners are notified by email.

Bulk data

For historical backfills and data-warehouse loads, use export jobs (POST /v2/exports) instead of paging through the readings endpoint. An export job covers up to 31 days of raw readings and produces a compressed CSV or Parquet file. Temporary limit increases for migrations are no longer granted; export jobs are the supported alternative.
